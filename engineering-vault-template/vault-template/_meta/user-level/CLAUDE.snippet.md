## 个人知识库（engineering-vault）

我的个人知识库在 `{{VAULT}}`：Obsidian vault，同时是 git 仓库（你自己的 GitHub 私有仓库）。

### 主动记录通用知识

工作中发现了以后还会用到的东西，就记进知识库，不用等我开口：不显而易见的发现、器件/协议/工具的坑、解决疑难问题的方法、某个设计选择背后的通用理由、值得保留的参考。只记可复用的结论，不记步骤流水账。

不要记：

- 项目内部细节、客户信息、公司名称、未公开的设计、内网地址。
- 任何密码、token、密钥。
- 拿不准能不能记的内容：不记，或者问我一次。

记之前先把内容通用化，去掉项目和公司背景。例如写成“ST25DV 的 GPO 是 open-drain 输出，需要外部上拉”，而不是“某个项目里 GPO 不工作”。

怎么记：

1. 先读 `{{VAULT}}\CLAUDE.md`（本会话读过就不必重读），按它的约定写到 `{{VAULT}}\knowledge\<主题>\YYYY-MM-DD-主题.md`，主题用小写英文。
2. frontmatter 里 `source: claude`、`ai_generated: true`、`reviewed: false`，写一句话 `summary`。
3. 先搜索已有笔记（`{{VAULT}}\knowledge` 下 grep 关键词）；已有就追加并更新 `updated`，不要新建重复的，不要改写原有内容。
4. 写完在知识库里提交并推送：`git -C {{VAULT}} add <文件>`、`git -C {{VAULT}} commit -m "vault: add knowledge <主题>"`、`git -C {{VAULT}} push`。不要强推。
5. 不要为此打断正在做的任务；记完最多用一句话说明记在了哪个文件。

永远不要删除知识库里的文件，也不要覆盖已有内容。

### 查阅

任务可能已经有记录时（以前查过的器件、协议、某个坑的解决办法），先到 `{{VAULT}}` 里查一下（读 `Index.md`，或 grep 关键词），再决定要不要从头研究。是否值得查由你判断，不是每个任务都需要。
